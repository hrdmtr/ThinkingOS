# Thinking OS（仮称）Step 4｜ドッグフーディング期間の設計

> Step 4成果物。MVP完成後に実施する検証期間の設計。

---

## 1. 期間

**4週間**。

MVPはまだ未成熟な段階から使い始めることになるため、まずは短いサイクルでフィードバックを得て軌道修正できるようにする。4週間で明確な傾向が出なければ、設計を見直したうえで次の4週間に延長する判断もありうる（最初から8週間固定にはしない）。

## 2. 計測方法

比較対象となる既存製品が存在しないため、他製品との相対比較（「何倍速いか」等）による検証はそもそも成立しない。代わりに、セッションごとの命題数と、累計で蓄積された命題・関係の数という絶対的な統計そのものを指標として採用する（`thinking-os-plan-v0.2.docx` セクション6のv0.2改訂を参照。旧版にあった「体感目標：10倍」は根拠のない数値だったため撤回した）。

- **命題の定義**：新規に作成された「アイデア」または「仮説」タイプのノードを1件とカウントする。「根拠」「判断」「未解決事項」「タスク」タイプは、命題そのものではなく命題を支える付随情報のため、主指標のカウント対象には含めない（別途、参考指標として集計してもよい）。
- **セッション単位の統計**：壁打ちセッション終了ごとに、そのセッションで新規作成された命題数を表示する（例：「今回の壁打ちで生まれた命題：3件」）。
- **累計の統計**：これまでに蓄積された命題の総数、および確定済みの関係（エッジ）の総数を常に表示する（例：「これまでに整理した命題：42件、作成した関係：15件」）。これはMVP画面の「最近更新された知識」等と合わせて表示する常設の指標とする。
- **週次の集計**：上記に加えて、撤退・継続基準の判断のために、毎週末にその週に新規作成された「アイデア」「仮説」ノードの件数を集計する。
- **命題／時間の算出**：その週に壁打ちへ費やした時間（会話ログのタイムスタンプの合計、または自己申告の簡易タイマー）で命題数を割る。これは参考指標とし、合否判定には使わない（詳細は4章）。
- **抽出タイミング**：Step 5で「バッチ処理（セッション終了後）」に確定済み。上記の集計は全てセッション終了時点のバッチ処理結果を基準に行う。

## 3. 比較対象

**主観的な事後振り返り**を採用する。

厳密なA/Bや交互デザイン（使用週／非使用週を分ける）は運用負荷が高く、n=1のドッグフーディングでは継続の妨げになりやすいと判断し、見送る。代わりに、各週末に以下を短く記録する。

- 「壁打ちをしなかった場合と比べて、今週はどのくらい思考が進んだと感じたか」を5段階程度の主観評価で記録
- 「今週、壁打ちがなければ思いつかなかったと思うアイデア・仮説」があれば1〜2件メモする

これらは定量指標（命題数）を補う定性的な裏付けとして使う。数値化された比較対象がない分、結論の強さは限定的であることを認識した上で運用する。

## 4. 撤退基準／継続基準

企画書v0.1にあった「思考の整理速度10倍」という体感目標は、比較対象となる既存製品がなく検証手段もないため、合否基準からは正式に外す。以下の基準はすべて、命題数の増減傾向と主観評価のみで判断する。

- **継続基準**：4週間を通じて命題数が横ばい以上（週を追うごとに減少しない）、かつ主観評価で「壁打ちなしより思考が進んだ」と感じる週が半数以上ある場合、本格開発（Step 5以降の実装）に進む。
- **見直し基準**：以下のいずれかに該当する場合は、コンセプト（AIの責務範囲、知識モデル、UI等）を見直す。
  - 命題数が2週連続で明確に減少している
  - 「今日の問い」等の想起機能を開き続ける習慣がつかず、使用自体が続かない
  - 主観評価で「壁打ちなしと大差ない」と感じる週が過半数を占める
- **中断基準**：4週間の途中でも、使用が明らかな負担になっている（Step 1で確定した「思考力を退化させない設計」という前提に反する体感がある）場合は、期間満了を待たずに一旦中断して設計を見直す。
