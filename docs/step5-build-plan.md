# Thinking OS（仮称）Step 5｜構築計画・要件定義

> Step 5成果物。企画書（`thinking-os-plan-v0.2.docx`）セクション6・8の方針を、実装に落とせる粒度まで具体化したもの。

---

## 1. ノード抽出パイプラインの実装方式

**バッチ処理（会話セッション終了後）を採用する。**

- 会話セッションの終了（明示的な終了操作、または一定時間の無操作）をトリガーに、そのセッションの会話ログ全体をまとめてAIに渡し、アイデア／仮説／根拠／判断／未解決事項／タスクを抽出する。
- リアルタイム処理（発言ごとに都度推論）は、実装の複雑さとレイテンシがUXに影響するリスクがあるため見送る。将来的にMVPの手応えを見てから検討する。
- 抽出結果・関連候補は、次回起動時に「今日の問い」「最近更新された知識」として提示する。会話中に即座に関連候補が出る体験は持たない（v0.1で優先度が後退した「毎朝ひとこと話しかける」機能とは別軸の割り切り）。

## 2. データ永続化方式

企画書セクション8の方針（グラフDBは導入せず、軽量な構造から始める）を踏まえ、以下を最小構成とする。

- **保存先**：ローカルのSQLiteを1ファイルDBとして使う（軽量・単一ユーザー・後からの移行が容易という理由。特定の言語・フレームワークへの依存はここでは規定しない）。
- **nodesテーブル**：`id`, `type`（アイデア／仮説／根拠／判断／未解決事項／タスク）, `content`, `created_at`, `session_id`。単一テーブルとし、typeごとにテーブルを分けない（企画書セクション8の方針通り）。
- **edgesテーブル**：`id`, `source_node_id`, `target_node_id`, `label`, `strength`（任意）, `discovered_at`。AIが提示した関係候補は、ユーザーが確定した時点で初めてこのテーブルに書き込む。AIが提示しただけの未確定候補は永続化しない（毎回のバッチ処理で再提示されればよいため）。
- **エッジラベルの語彙**：初期候補「対比」「帰結」「想起」を自由入力可能なテキストカラムとして持たせ、固定リストへの強制はしない（この決定を企画書本体セクション8に反映済み。旧セクション11にあった当該の未解決論点は解消済みとして削除した）。

## 3. エッジ候補提示UI（AI提案→ユーザー確定のフロー）の最小設計

- 起動時の「今日の問い」「最近更新された知識」画面から、各ノードに対して「関連候補」を一覧表示する。
- 各候補には、AIが提示した関係ラベルの初期案（例：「対比」）と、対象ノードの内容が並ぶ。
- ユーザーの操作は3択：
  1. **確定**：提示されたラベルのまま確定 → edgesテーブルに保存
  2. **修正**：ラベルをテキストで書き換えてから確定 → 書き換えた内容で保存
  3. **却下**：関連なしとして破棄 → 何も保存しない（AIは同じ候補を毎回作り直してよい。却下履歴の学習はMVP対象外）
- 「聞き返し」（企画書セクション7）は、確定・修正いずれの操作の際にも、ユーザーが望めば「なぜこの関係だと思ったか」をAIに尋ねられる導線を用意する（常時表示のラベルや根拠表示は行わない）。

## 4. 「毎朝ひとこと話しかける」機能の要否・優先度

**MVP対象外とし、将来機能に位置づける。**

- 企画書v0.1では中心機能候補だったが、v0.2の議論でノード・エッジの永続化パイプラインより優先度を下げる方針が確定済み（企画書セクション6・10）。
- MVP成功基準は「壁打ちからの新規着想」「整理速度」を命題数で測ることであり、これはユーザー起点の壁打ちセッションがあって初めて計測できる。プッシュ型の声かけ機能がなくても指標は測定可能なため、MVPの必須要件ではないと判断する。
- 将来機能としては維持し、ドッグフーディングの結果次第で優先度を再評価する。

## 5. 統計表示（セッション単位・累計）

企画書v0.2の改訂（セクション6）およびStep 4（`docs/step4-dogfooding.md`）を踏まえ、MVPの表示要素に以下を追加する。比較対象となる既存製品がないため、他製品比の速度倍率のような相対指標ではなく、絶対的な統計そのものを画面に表示する。

- セッション終了時：「今回の壁打ちで生まれた命題：N件」を表示
- 常設表示（「最近更新された知識」等と並べて）：「これまでに整理した命題：NN件、作成した関係：MM件」
- これらはnodes／edgesテーブルの件数をそのまま集計すればよく、追加の分析処理は不要。
